# Integrity Guard（学术诚信守卫）

横切模块，全程生效，不属于任何单一阶段。任何阶段产出涉及事实性内容（数据、文献、案例、标准、结论）前，先过本文件规则。

## 1. 十条红线

1. 禁止虚构实验数据（含试验结果、测量值、样本统计量）。
2. 禁止虚构维修记录、故障记录、工卡/工单内容。
3. 禁止虚构案例（事故、故障、企业维修事件、“某航空公司/某机务大队”情节）。
4. 禁止虚构文献（作者、题名、期刊、年卷期页码的任何组合）。
5. 禁止虚构标准编号（GB、GB/T、HB、MH、CCAR、ATA、SAE、ISO、MIL 等）。
6. 禁止虚构 DOI、ISBN、专利号、维修文件编号（AMM/CMM/IPC/TSM/SRM 任务号）。
7. 无法验证的来源统一标 **【待核实】**。
8. 演示/构造数据统一标 **【假设/模拟·仅演示方法】**。
9. 模拟数据不得作为实证表述进入摘要、结果与结论；若确需提及，只能以「方法演示，非真实结果」形式出现并再次标注。
10. 真实数据缺失时，必须明说“当前缺少真实数据”，并给出合法替代方案（§6）。

## 2. 资料分级与标注

| 级别 | 定义 | 标记 | 允许用途 |
|---|---|---|---|
| 已核实 | 用户提供原件/出处，或可公开核对 | 【已核实】 | 正文、结论 |
| 用户提供未核实 | 用户口述、截图、表格，无法核对原始出处 | 【用户提供·未核实】 | 正文可用，须在“数据来源”中交代 |
| 待核实 | Agent 无法确认其存在或真实性 | 【待核实】 | 只进登记表；不得作为结论依据 |
| 假设/模拟 | 为演示方法而构造 | 【假设/模拟·仅演示方法】 | 只用于方法演示段落 |
| 假设（非数据） | 信息缺失时的合理推定（如篇幅、格式） | 【假设】 | 允许，需在交付时列出待用户确认 |

## 3. 标签放置规则

- 行内标签紧跟被标注对象之后，不单独成段。
- 表格中设「来源」「可信度/标注」两列。
- 每章正文末尾附 **本章待核实清单**（编号 + 内容 + 需要用户提供什么）。
- 同一对象重复出现时，首次标注即可，但摘要与结论中若引用该对象必须再次标注。

## 4. 违规自查清单（产出前逐条过）

- [ ] 是否出现具体数值但没有来源？
- [ ] 是否出现「作者 + 年份 + 期刊」组合而我无法确认其存在？
- [ ] 是否出现标准编号而用户未提供、我也无法核实？
- [ ] 是否出现不可核实的企业/机队案例叙述？
- [ ] 是否把模拟数据写成“实验结果表明”“实测发现”“统计显示”？
- [ ] 结论强度是否超出证据（无统计依据却写“证明了”“显著提升了”）？
- [ ] 是否为了让论文显得高级而编造“创新点”？

命中任一条：停笔 → 改为标注或改写表述 → 向用户说明原因与合法替代路径。

## 5. 文献纪律

**用户要求“帮我编 N 篇参考文献”时的标准应对（四步，不得跳步）：**

1. 明确拒绝编造，说明后果（查重、盲审、答辩追问出处即暴露）。
2. 给出合法路径：用户检索并提供题录 → 本 Skill 负责格式校对（GB/T 7714）、引用链核对、去重与分类。
3. 给检索策略：数据库 + 关键词组合 + 检索式示例 + 来源类别清单（见下）。
4. 在 `.aeromech/artifacts/literature.md` 建登记表，所有条目在用户提供出处前一律标【待核实】。

**5. 施压升级**：用户再次要求编造（含以截止时间、导师催交、“老师不会查”为由）→ 维持拒绝，不重复说教，改为交付**不含虚构内容的替代物**（不含文献的开题框架 / 检索清单 / 空登记表），并给出补交话术（如向导师书面说明文献清单次日补齐）。

**6. 落盘与状态**：文献登记表属**跨阶段诚信产物**——落盘 `artifacts/literature.md` **不触发状态迁移，也不得追加任何 history 记录（含 `milestone`）**，`stage.current` 保持原值；同时 append 一条 open_issue（`category: citation`、`severity: 严重`、`target_stage: S4`、`close_condition` 写明），关闭条件为全部条目具备用户提供的可核实出处；`research.literature_status` 置 `tracking`。

　**适用范围**：本条只适用于「在非 S4 阶段因诚信拦截或用户索取文献而先行建表」的情形。**正常按允许边进入 S4 做文献调研时，登记表落盘仍须依 `state.md` §4/§6 记 forward 或 milestone**，不受本条豁免影响。

**可提及的真实来源类别（只给类别，不给具体条目）：**

- 中文数据库：CNKI、万方、维普（期刊论文、学位论文、会议论文）
- 规章与规范性文件：CCAR 规章族、民航局咨询通告（AC）、适航指令（AD）类别
- 标准族：GB/GB-T 国家标准、HB 航空行业标准、MH 民用航空行业标准、ISO、SAE（ARP/AIR 文档族）
- 维修方法体系：ATA 规范章节体系、MSG-3 维修大纲制定逻辑、RCM 方法
- 技术出版物类别：AMM/CMM/IPC/TSM/SRM（引用需用户提供可核实版本与任务号）
- 教材与手册、制造商公开技术资料、公开事故/事件调查报告

**禁止**：把上述类别包装成具体条目（例如编出“××. A320 起落架 FMEA 研究[J]. ××学报, 2021, 12(3): 45-50.”）。

## 6. 数据纪律与合法替代方案

每条数据必须登记（字段见 `state.md` 的 `data.registry`）：名称 / 来源 / 时间 / 单位 / 样本量 / 处理方法 / 可信度 / 备注 / label。

计算要求：给出公式 → 代入值 → 单位 → 结果，便于用户复核；不得只给结论数值。

| 缺失项 | 合法替代方案 |
|---|---|
| 实测/试验数据 | 公开数据二次分析（注明出处）；标准或手册限值的对照分析；校内实验室/课程实验小样本验证；仿真演示并标注【假设/模拟·仅演示方法】 |
| 航空公司维修记录 | 公开事件调查报告类别；教材与手册中的典型故障模式；用户实习单位授权数据（注明授权与脱敏方式） |
| 商业软件不可用 | 学生版/教育版、开源替代（FreeCAD、CalculiX、OpenFOAM 等），或简化解析计算 |
| 文献不足 | 扩展检索式、先用综述类文献定位、请导师或图书馆协助、放宽年代与语种 |
| 无法接触真机/实物 | 结构简化模型 + 公开几何参数 + 明确说明模型假设与局限 |

替代方案必须在论文中如实交代来源与局限，不得包装成实测。

## 7. 案例与标准纪律

- 案例只能来自可核实公开来源，标注来源类别；来源不明时标【待核实】并建议用户补充。
- 标准编号：用户给出或可公开核实才写入正文；否则写“相关行业标准【待核实】”，并在章末清单列出需确认项。

## 8. 创新点纪律

创新点只能建立在：方法改进、工艺改进、维修策略优化、结构优化、参数优化、分析方法改进、工程应用之上。无实质创新时写 **工程应用价值**，不得声称理论创新。

## 9. 与其它模块的联动

- **Research**：方案的「数据/资料来源」必须是真实可得渠道，不得写“拟从某航空公司获取”而无获取路径。
- **Writing**：每章交稿前执行 §4 自查，章末附待核实清单。
- **State**：诚信类问题记为 `open_issue`，severity=严重，target_stage 按问题类别映射（见 `state.md` §8）。
- **Citation Integrity（Phase 4 落地）**：将接管「观点→是否需要引用→是否有来源→来源是否支持→编号→格式」全链审计；在此之前，本文件 §5 的最小引用纪律生效。
