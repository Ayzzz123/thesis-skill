# 模板：题目卡片（Topic Card）

由 `agents/topic.md` 填写。字段名与顺序不得增删改；无内容写「暂无」或【假设】+说明。

## A. 题目分析卡（S1，用户已有题目）

```markdown
# 题目分析卡

- 题目：<原始题目，不改写>
- 专业匹配度：<高/中/低> —— <一句话依据：与××专业核心课程/岗位能力的对应>
- 研究方向：<如：飞行器维修工程 / 航空机械结构 / 可靠性与维修性>
- 研究对象：<具体到系统或部件，如：A320 起落架系统（收放与减震部分）>
- 核心问题：<一句话，可用“××存在××问题，需通过××解决”句式>
- 研究方法：<主方法 + 辅助方法，如：FMEA 为主，辅以故障树与维修策略对比>
- 数据需求：<需要什么数据/资料，来源渠道是否可得；不可得则写明并给替代方案>
- 软件/工具需求：<必需 / 可选 / 无需；标注用户是否具备>
- 难度：<低/中/高> —— <依据：方法复杂度、数据可得性、数学要求>
- 可行性：<可行 / 有条件可行 / 不建议> —— <条件或理由>
- 风险：<2–4 条：范围过大、数据不可得、软件不具备、结论无法验证等>
- 修改建议：<题目收缩或改写建议；若题目已合适写“无需修改”>
- 初判论文类型：<research / review / design>（最终由 S3 确认）
- 范围与条件自检：<见 topic.md §4 红线清单，逐条 是/否 + 处理>
```

## B. 候选题目卡（S2，用户无题目，每个候选一份）

```markdown
### 候选 <n>：<题目>

- 为什么适合：<与用户专业、兴趣、数据条件、软件条件、时间的匹配理由>
- 研究对象：<系统/部件/工艺对象>
- 研究方法：<主方法>
- 数据需求：<数据来源与可得性>
- 难度：<低/中/高>
- 风险：<1–3 条>
- 工程应用价值：<对维修实践/工艺/管理的具体用处，不写空话>
```

候选数量：3–5 个，覆盖不同难度与方法；必须至少 1 个「低难度保底」与 1 个「中难度推荐」。

## C. 排除清单（生成候选时同步输出）

不适合本科/高职论文的题目特征，命中即排除并说明原因：

- 需要实验室台架、真机试车、风洞等用户不具备的条件；
- 依赖航空公司/制造商内部维修记录且无获取渠道；
- 依赖高价商业软件且用户无授权（可给开源/学生版替代）；
- 研究对象过宽（如“飞机维修体系研究”“航空发动机全寿命管理”）；
- 需要研究生级数学模型（随机过程、非线性动力学、多物理场耦合）而用户基础不足；
- 结论无法由本科阶段可得证据支撑。

## D. 字段判定标准

| 字段 | 取值标准 |
|---|---|
| 专业匹配度 | 高=直接对应专业核心课与岗位；中=相关方向；低=跨专业，需说明可行性 |
| 难度 | 低=资料可得+方法常规；中=需一定数据处理或软件操作；高=需仿真/试验或多方法耦合 |
| 可行性 | 可行=条件齐备；有条件可行=需用户补齐（列出）；不建议=触碰排除清单 |
