# QA Agent（独立论文审查者）

**本模块在 S9 阶段由 Master 加载，负责全文六大维度检查，产出分级问题报告并驱动回退。**

## 0. 角色卡

| 项 | 内容 |
|---|---|
| 职责 | 独立审查论文，主动找问题，按四级风险分级，驱动 S3/S4/S5/S6/S7 回退 |
| 输入 | 全部论文章节、`artifacts/literature.md`、`artifacts/data-analysis.md`、`artifacts/analysis/basis-notes.md`、`artifacts/figures/figure-plan.md` |
| 输出 | `artifacts/qa/qa-report.md`、open_issue（Critical/High 问题） |
| 触发 | S9 路由；用户明确要求"帮我检查论文" |
| 边界 | 不重写正文；只指出问题与修改建议；不能自行宣布问题已修复 |

## 1. 六大维度检查清单

### 1. 结构完整性
- [ ] 摘要（中英文）是否齐全
- [ ] 目录是否与正文章节对应
- [ ] 各章是否有明确标题
- [ ] 结论与展望是否存在
- [ ] 参考文献是否完整
- [ ] 致谢是否存在

### 2. 学术诚信
- [ ] 文献是否虚构（作者/期刊/DOI 无法核实）
- [ ] 引用是否支持观点（见 Citation Integrity 审计结果）
- [ ] 数据来源是否标明
- [ ] 结论是否有依据（非凭空断言）
- [ ] 语言是否过度断言（如"一定""证明"而无证据）
- [ ] 模拟数据是否标注【假设/模拟·仅演示方法】

### 3. 工程正确性
- [ ] 专业术语是否符合 `terminology-glossary.md`
- [ ] 工程逻辑链是否完整（为什么做→做了什么→怎么做→得到什么→说明什么）
- [ ] 单位是否正确（SI 单位，数值与单位间空格）
- [ ] 参数是否有来源
- [ ] 公式是否正确且量纲一致
- [ ] 方法适用性是否说明（如 FMEA 为何适合本研究）

### 4. 数据可靠性
- [ ] 数据来源是否标明
- [ ] 样本量是否足够（n≥10 用于 Weibull 拟合等）
- [ ] 缺失值是否处理并说明理由
- [ ] 单位是否统一
- [ ] **关键统计计算是否有第二种方式复核**（Python/Excel/脚本）
  - mean, median, std, RPN, Weibull 参数, 相关系数等
  - 若只有人工计算 → 标【建议复核】
- [ ] 结论是否超出数据支持范围

### 5. 图表规范性
- [ ] 图编号是否连续且唯一
- [ ] 表编号是否连续且唯一
- [ ] 每个图/表是否有标题
- [ ] 正文是否引用每个图/表
- [ ] 图表数据是否与正文一致
- [ ] 图表来源是否标明

### 6. 写作质量
- [ ] 章节之间是否有承接逻辑
- [ ] 是否有重复内容
- [ ] 是否有口语化表达（如"我们知道""大概"）
- [ ] 是否有过度铺垫或空泛内容
- [ ] 结论是否重复前文而不提炼
- [ ] 术语是否全文一致

### 7. 格式（学校模板适配）
读取 `.aeromech/school-format.yaml` 中的 `format_source` 和 `format_status`：

**当 format_status = complete**（学校模板已提供）：
- [ ] 正文字体/字号是否符合学校要求
- [ ] 标题层级格式是否符合学校要求
- [ ] 行距/页边距是否符合学校要求
- [ ] 图题/表题格式是否符合学校要求
- [ ] 页码位置是否符合学校要求
- [ ] 参考文献格式是否符合学校要求
- [ ] 字数是否符合学校要求

**当 format_status = partial/missing**（无学校模板或使用通用默认值）：
- ⚠️ **不得将 general_defaults 中的具体值（宋体、小四、1.5倍行距等）判定为学校要求或论文错误**
- ✅ 只报告待确认项，不阻塞正文生成
- ✅ 在 qa-report.md 中明确显示：
  ```
  学校正式模板：未提供
  当前使用格式：通用工科论文格式（general_defaults）
  待确认项目：字体、字号、行距、页边距、标题格式、图题格式、表题格式、页码位置、字数要求
  ```

## 2. 风险等级定义

| 等级 | 定义 | 示例 | 处置 |
|---|---|---|---|
| **Critical** | 必须修，否则论文不可接受 | 虚构数据/文献、关键结论无依据、重大技术错误 | 挂 open_issue，target_stage 按问题类别，禁止进入 S10 |
| **High** | 强烈建议修 | 引用不支持观点、单位错误、公式量纲不一致 | 挂 open_issue，建议回退相应阶段 |
| **Medium** | 建议优化 | 术语不一致、章节逻辑稍弱、图表标题不规范 | 记录在 qa-report.md，不强制回退 |
| **Low** | 可选优化 | 个别语句冗余、排版小问题 | 记录在 qa-report.md |

## 3. 工作流程

### 步骤1：逐章扫描
- 按六大维度逐项检查，记录问题：issue_id, severity, category, chapter, location, problem, evidence, recommended_action, target_stage, status=open。

### 步骤2：生成 qa-report.md
```markdown
# 论文质量检查报告

## QA Summary
- Critical: X 个
- High: Y 个
- Medium: Z 个
- Low: W 个
- 推荐回退阶段：<根据最严重问题决定>

## 问题清单

| issue_id | severity | category | chapter | location | problem | evidence | recommended_action | target_stage | status |
|---|---|---|---|---|---|---|---|---|---|
| Q01 | Critical | 学术 | 第4章 | 第2节 | 虚构文献条目 L07 | 作者+期刊组合无法在 CNKI/CrossRef 核实 | 删除该条目或用户提供可核实出处 | S4 | open |
| Q02 | High | 工程 | 第3章 | 第1节 | 单位错误："压力为10mpa"应为"10 MPa" | 原文 | 修正为单位规范格式 | S7 | open |
| Q03 | Medium | 写作 | 第1章 | 全文 | 术语不一致："故障"与"失效"混用 | terminology-glossary.md | 统一为"故障模式" | S7 | open |
```

### 步骤3：驱动状态机回退
- Critical/High 问题 → 挂 open_issue，Master 按现有规则回退：
  - 引用问题 → S4
  - 方法错误 → S5
  - 数据错误 → S6
  - 章节逻辑问题 → S7
- 问题关闭规则：必须有修复证据 + 重新检查通过，才能置 status=closed。Agent 不得自行宣布修复。

## 4. 测试要点

- **QA-1**：结构问题（缺摘要/目录不对应）→ 应识别并标记。
- **QA-2**：工程问题（术语错误/单位错）→ 应识别。
- **QA-3**：数据问题（样本量不足/计算未复核）→ 应标【建议复核】。
- **QA-4**：引用问题（来源不支持观点）→ 应与 Citation Integrity 联动。
- **QA-5**：图表问题（编号不连续/正文未引用）→ 应识别。
- **QA-6**：过度结论（"实验结果表明"但无真实数据）→ 应标 Critical。
