# 飞机系统分析知识卡（aircraft-systems）

**本卡只在 S3/S5 阶段由 Engineering Agent 加载，用于建立"系统功能 → 故障 → 影响"的工程链。**

## 1. 系统工程分解框架

| 层级 | 定义 | 示例（起落架系统） |
|---|---|---|
| **系统** | 完成特定飞行/地面功能的整体 | 起落架系统 |
| **子系统** | 系统中承担子功能的模块 | 收放子系统、减震子系统、锁止子系统 |
| **部件** | 子系统中的物理单元 | 收放作动筒、上位锁销、减震支柱 |
| **功能** | 部件/子系统应执行的任务 | 将起落架从放下位转换到收上位并锁定 |

## 2. 功能链建模（输入→处理→输出）

每个功能环节必须明确：

- **能量源**：液压压力、电力、气压、机械力
- **控制**：手柄、电门、传感器、逻辑电路
- **作动**：作动筒、马达、阀门
- **反馈**：位置指示、压力传感器、微动开关

**示例**：收放功能链
```
能量源（液压泵） → 控制（收放手柄+选择阀） → 作动（收放作动筒） → 反馈（位置传感器+指示灯）
```

## 3. 故障传播路径

故障从部件级向系统级传播的典型路径：

```
部件失效（密封件老化） 
  → 子系统功能丧失（作动筒内漏，压力不足） 
    → 系统功能失效（起落架无法放下） 
      → 最终后果（着陆时机体损伤）
```

**规则**：分析时必须逐层追踪，不得跳步。每一层的输出是下一层的输入。

## 4. 交联系统识别

飞机系统之间存在功能交联，需识别：

- **液压系统 ↔ 起落架**：提供收放动力
- **电气系统 ↔ 起落架**：提供控制信号与位置指示
- **飞控系统 ↔ 起落架**：空地逻辑互锁（空中禁止收放）

**分析方法**：列出与本系统有能量/信号/机械连接的所有外部系统，标注交联类型。

## 5. ATA 章节体系（概念说明）

ATA（Air Transport Association）规范提供了一种**系统分类与资料组织方式**，常用于维修手册编排：

- ATA 32：起落架
- ATA 29：液压动力
- ATA 21：空调/增压

**重要声明**：ATA 章节号是行业通用的**资料归类体系**，不是技术标准本身。具体机型某部件属于哪一 ATA 章节，**必须以用户提供的 AMM/CMM/IPC 为准**，不得自行推断。无来源时标**【待核实】**。

## 6. 常见错误（自查清单）

- [ ] 把系统名称当成功能（应写"执行什么任务"）
- [ ] 忽略能量源与控制环节，只写作动部件
- [ ] 未识别交联系统，导致故障原因遗漏
- [ ] 把 ATA 章节号当作技术依据引用（它只是归类方式）
- [ ] 在没有 AMM 出处的情况下声称某部件属于某 ATA 章

## 7. 使用场景

- **FMEA 前期**：用本卡的功能分解方法建立功能清单，作为 FMEA 表的"功能"列输入。
- **故障链分析**：用本卡的故障传播路径模板，从部件失效追溯到最终后果。
- **边界划定**：用本卡的交联系统列表，明确哪些外部系统纳入分析范围，哪些排除。
