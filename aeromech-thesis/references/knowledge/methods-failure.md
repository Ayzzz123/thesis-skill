# 故障分析方法知识卡（methods-failure）

**本卡只在 S3/S5 阶段由 Engineering Agent 加载。**

## 1. 故障链层级（严禁混用）

| 层级 | 定义 | 示例（起落架收放系统） | 禁止写法 |
|---|---|---|---|
| **现象/异常** | 可观察到的偏离正常状态的表现 | 收放手柄操作后舱门未动、位置指示异常 | 把现象当故障模式 |
| **故障模式** | 功能失效的具体形式（不能执行规定功能） | 起落架无法放下并锁定、舱门不能关闭 | 把零件名写为模式；把"磨损"直接当模式 |
| **故障原因** | 导致故障模式的物理/化学/人为机制 | 作动筒密封件老化内漏、锁销疲劳断裂、液压管路接头松动 | 不说明机制只写"磨损"；把模式当原因 |
| **局部影响** | 对所在子系统功能的直接影响 | 起落架停留在收上位、舱门处于半开位 | 把上层影响写在此处 |
| **最终后果** | 对飞行安全/运行能力的最高层级影响 | 着陆时起落架无法承受载荷导致机体损伤、复飞风险增加 | 把局部影响当最终后果 |
| **检测方法** | 能发现该故障的手段 | 地面功能测试、目视检查、压力测试、NDT | — |
| **隔离措施** | 确定故障部位的方法 | 分段加压测试、部件替换法 | — |
| **维修处置** | 修复或缓解的行动 | 更换密封组件、重新紧固接头、调整间隙 | — |

**规则**：分析时必须逐层推进，不得跳步。每一层的输出是下一层的输入。

## 2. FMEA（故障模式与影响分析）

### 目的与适用条件
- **目的**：系统性识别功能失效模式，评估风险优先级，指导维修策略优化。
- **何时使用**：研究对象有明确的功能分解；需要量化比较不同故障模式的相对风险；维修资源有限需排序。
- **输入**：功能清单、已知故障记录、维修手册、专家经验（须注明来源）。
- **输出**：FMEA 表（含 S/O/D/RPN）、高风险模式清单、推荐维修措施。

### 核心字段定义
| 字段 | 定义 | 评分要点（通用口径，非行业标准） |
|---|---|---|
| **Failure Mode** | 功能如何失效 | 具体、可观察、不与原因混淆 |
| **Failure Cause** | 导致失效的机制 | 物理/化学/人为因素，可追溯 |
| **Failure Effect** | 局部影响 + 最终后果 | 分层表述，不混为一谈 |
| **Severity (S)** | 后果严重度（1–10） | 1=无影响，10=灾难性（人员伤亡/飞机损毁） |
| **Occurrence (O)** | 发生频度（1–10） | 1=极罕见，10=几乎必然；需有数据或合理推断依据 |
| **Detection (D)** | 现有检测手段的发现难度（1–10） | 1=极易发现，10=几乎无法在役发现 |
| **RPN** | Risk Priority Number = S × O × D | 范围 1–1000；数值越大风险越高 |
| **Recommended Action** | 降低风险的维修/设计措施 | 具体、可执行、与 RPN 高低匹配 |

**重要声明**：上述 S/O/D 分档描述为**通用工程口径**，不是某标准或机型的正式规定。若论文采用特定来源的评分表（如某教材、某企业规范），必须在 `basis-notes.md` 中写明「【本文采用口径】源自 XXX」，并与「【来源规定】」区分。无来源时不得伪装成行业标准。

### FMEA 常见错误（自查清单）
- [ ] 把零件名称写成故障模式（应写功能失效形式）
- [ ] 把"磨损/腐蚀"直接作为原因而不说明机制（应写"密封件因长期受压产生永久变形导致内漏"）
- [ ] 局部影响与最终后果混淆（应分层）
- [ ] S/O/D 无依据地随意赋值（应有评分理由或在 basis-notes 中说明为模拟演示）
- [ ] 仅按 RPN 排序而不讨论其局限（RPN 相同但 S 不同的模式需单独复核）
- [ ] 用 RPN 代替工程判断（高 RPN 不一定等于必须立即处理，需结合成本/可行性）
- [ ] 数据缺失时强行填分数（应标【待核实】或【假设/模拟·仅演示方法】）
- [ ] 把模拟案例写成真实故障统计（必须显式标注）

## 3. FTA（故障树分析）

- **何时使用**：已知顶层故障后果，需逆向追溯所有可能的基本原因组合；适合分析复杂系统的多路径失效。
- **顶事件**：不希望发生的顶层故障（如"起落架着陆时无法承载"）。
- **中间事件**：导致顶事件的子系统级失效。
- **基本事件**：不可再分的底层原因（部件失效、人为失误、环境因素）。
- **逻辑门**：AND（所有输入事件同时发生才触发）、OR（任一输入事件发生即触发）。
- **与 FMEA 区别**：FMEA 自下而上（从功能到后果），FTA 自上而下（从后果到原因）；FMEA 适合枚举单点失效，FTA 适合分析多因素组合失效。

## 4. RCA / 5 Why（根本原因分析）

- **适用条件**：已发生的具体故障事件，需找出根因以防止复发。
- **根因 vs 直接原因**：直接原因是表象（如"螺栓断裂"），根因是深层机制（如"装配扭矩未按工艺要求执行且无复检程序"）。
- **规则**：追问"为什么"直到找到可采取系统性纠正措施的层面；不能无限追问；每一步必须有证据支持，不能仅凭经验认定。
- **证据闭环**：根因必须能通过实验、数据或逻辑推导验证。

## 5. 方法选型决策表

| 问题特点 | 优先方法 | 原因 |
|---|---|---|
| 需系统枚举功能失效模式并排序 | FMEA | 结构化、可量化、适合维修策略优化 |
| 已知顶层后果需追溯多路径原因 | FTA | 逆向分析、适合复杂系统组合失效 |
| 已发生具体事件需防复发 | RCA / 5 Why | 聚焦根因、证据驱动 |
| 数据充足需统计规律 | 可靠性分析（Weibull/MTBF） | 基于样本推断总体 |
| 结构强度/变形需校核 | 有限元分析 | 物理场仿真 |

**Engineering Agent 应按此表自动选择方法，并在 `basis-notes.md` 中写明选择理由。**
