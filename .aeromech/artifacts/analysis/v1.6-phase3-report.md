# v1.6.0 Phase 3 报告 — Thesis Orchestrator

> 日期：2026-09-15 · 分支：`feature-1.6.0-full-stack-orchestration`（未触碰 master / 协作者分支）
> 核心交付：`scripts/thesis_orchestrator.py` + tests/v1_6 四文件（91 断言）。全部旧测试与 Phase 1/2 测试原样绿。

## 1. Orchestrator

唯一入口 `python thesis_orchestrator.py <root> <status|step|drive|resume|run-loop|apply-human|gate|actions>`。
职责严格按指令 §一 收口：读状态（thesis_state）→ 建上下文（research_context）→ 调用 `stage_routing.route()`（**不自判 S1-S10**，指令 §四）→ 判下一动作 → 执行允许动作 → 经 StateIO 落结果（非法边拒绝不落盘，指令 §五）→ checkpoint → 校验 → 失败进恢复。研究判断（诊断/修复/RQG/loop）一律进程内直调 v1.4/v1.5 既有函数（`RDIA.diagnose/RRP.plan/RRP.execute/RQA.run/AL.run_loop/RRP.apply_human`），编排层零业务逻辑复制，不重写 Agent Loop / Registry。

## 2. Action Model（指令 §三）

每个动作追加一条 JSONL：`artifacts/analysis/orchestrator-actions.jsonl`，字段 `{action_id: ACT-XXXX, stage, reason, input, output, status, timestamp}`（`actions --last N` 可查）。状态值复用统一词表（PASS/WARN/FAIL/NEEDS_HUMAN_REVIEW/BLOCK/ROLLBACK/REPAIR/RETRY/ERROR…item 级语义）。`step()` 动作集：`RUN_PENDING / ADVANCE / ROLLBACK / NEEDS_UPSTREAM_WORK / HUMAN_REVIEW / BLOCK / RETRY_EXHAUSTED / STATE_DRIFT / ADVANCE_REJECTED / FINALIZE`。无静默执行：route 返回什么就执行什么并记录什么。

## 3. 主循环与 RUN_PENDING

`LOAD STATE → CONTEXT → ROUTE → PREREQS → EXECUTE → CHECKPOINT → VALIDATE → NEXT`（step/drive 实现；drive 有 `max_steps` 上限 25 防编排级循环）。route 返回 `SKIPPED_WITH_REASON` 时**必须执行对应 pending 工具**（`AI_EXECUTOR` 映射：feasibility/diagnosis→`research_diagnosis`；coverage→`research_quality_qa`；figure_traceability→trace+diagnose；agent_loop/full_qa→`research_agent_loop`），每步执行一个保持 Action 粒度；出口产物缺失时返回 `NEEDS_UPSTREAM_WORK`（写作/登记属 Agent 职责，编排层不代做研究、不硬推进）。

## 4. Checkpoint 与 State 集成

阶段迁移只经 `TS.transition`（合法边/触发源/override 确认/备份规则全部继承 Phase 1）；advance 记出口产物进 history evidence。每个重要 Action 后建 checkpoint（阶段完成 `stage:S?→S?`、AI 证据 `ai:*`、**失败恢复之前 `recovery-before-*`**、loop 完成 `agent-loop`），字段含 checkpoint_id/stage/task/ts/cursor/artifacts+sha256/registries 快照/qa_state/next_action（指令 §六）。

## 5. Resume（指令 §六/§七/§十二）

`resume`：drift 检查（见 §7）→ 硬错 ERROR(rc3)/软错人工(rc1)/干净则输出 RESUMED{stage, checkpoint, next(完整 route 判定), artifacts_ok, qa_state, cursor, next_action, from_start:false}。`from_start` 恒 False——**禁止从 S1 重启**。四中断点实测（test_resume 15 断言）：S3 后（恢复→接续 feasibility pending）、S5 计算中（游标 done=CALC-001、已完成产物 sha256 完好、续点指 CALC-002、不重跑不覆盖）、S7 章稿改动（ARTIFACT_CHANGED 拒绝默默续写）、S9 QA 中（诊断中间成果保留、续跑 full_qa）。state 不可读→ERROR 不伪造恢复。

## 6. Failure Recovery 五策略（指令 §七~九）

`classify_recovery(findings, state)` 由 **issue_type + severity + disposition（v1.5 权威通道）+ routing 阶段映射**共同决定，输出按 `block > rollback > human_review > repair > retry` 排序：
- 计算/写作类普通缺陷（disposition=auto）→ **REPAIR**：先 `recovery-before-repair` checkpoint → 复用 `research_repair.plan/execute`（白名单+before/after 留痕+复检，REP status 断言锁）→ 重新诊断；
- 研究设计类（FEASIBILITY_BLOCK/RQ_METHOD_MISMATCH/SCOPE_*/…）→ **ROLLBACK**：checkpoint → 自动挂 open_issue（category 映射）→ `TS.transition(revert)`（非法则 ok:False 不静默）；cur=目标阶段时转人工设计决策（v1.5 §3：仅限人工 REFRAME/LIMIT/ADD）；
- 证据冲突（UNRESOLVED_CONFLICT/queue 类）→ **HUMAN_REVIEW**：指向既有 `human-review-queue.yaml`（复用 v1.4.1/§六双队列，指令 §十六），不消费不代签；`apply-human` 委托 `RRP.apply_human`，裁决持久保留（rejected 不复活）；
- Critical 完整性（disposition=block ∧ critical/high；真实夹具：证据伪装 RI-E-DISGUISE）→ **BLOCK**：rc1，不改阶段不产 PASS，Action 日志留 BLOCK 记录；
- 工具瞬时失败 → **RETRY**（上限 1 次，二次失败 `RETRY_EXHAUSTED` 停止——不无限 retry，critical 绝不落 retry，两条都有断言）。
混合 findings 按最重策略优先；`Overall Score` 不参与放行（gate 五态断言锁，指令 §24）。

## 7. Drift 检测（指令 §十三~十五）

`drift_checks()` 三路合一，**发现差异绝不静默覆盖，state 零改写**：
- `ARTIFACT_MISSING` → ERROR；`ARTIFACT_CHANGED`（sha256 复算不一致）→ NEEDS_HUMAN_REVIEW（resume 拒绝默默继续）；
- `REGISTRY_DRIFT`：注册表内容已超 state 阶段（如 state=S5 而 claims/conclusions 已在）→ 人工确认；
- `STATE_DRIFT`：checkpoint 阶段与 state 不一致 → 人工确认；`STATE_INVALID`（validate 词表违规）→ ERROR。

## 8. Agent Loop 集成（指令 §十/§十一）

三场景全用真实 v1.5 夹具（不硬编 findings）：Auto Repair（claim_overstrength：loop 白名单改文+REP verified+loop-log 逐轮 issues_before/repairs/issues_after/improvement 字段断言）→ PASS 路径；Human Review（conflict_pending：队列未裁决不代签→人类 reject→apply-human→复跑不 BLOCK）；Critical（证据伪装→loop BLOCK→编排 BLOCK/gate 不产 PASS）。MAX_ITERATIONS=5 沿用 v1.5（`ORCH.LOOP_MAX_ITER==5` 断言，不重造旋钮）；超限/无改善即停由 loop 自身 `stopped_reason` 保证，编排层另有 `max_steps` 保护。**测试口径教训**：完整 v1.5 夹具（含 figures 注册）跑 loop 得 PASS_WITH_HUMAN_REVIEW（RQG-09/10 弱证据语义项属另一合法 NHR 队列 human-review.yaml）——夹具裁剪注册表会制造悬空引用→RQG BLOCK，属夹具失真而非编排 bug，已按真实终态口径校准断言。

## 9. Delivery Gate 消费（指令 §十七/§十八）

Orchestrator 通过 `SR.delivery_gate_status()` 读取研究侧五态/七态并原样消费（`gate` 子命令；`FINALIZE` 仅在 PASS/PASS_WITH_WARNINGS/PASS_WITH_HUMAN_REVIEW 放行）；格式 QA 全链聚合按计划在 Phase 4 接入。

## 12. 已知限制（如实记录）

1. **drive 是编排驱动器不是全自动代写**：`NEEDS_UPSTREAM_WORK`（章稿/分析产物缺失）明确交回 Agent 层——编排不生成论文内容，test-8.0（Phase 6）将验证 Agent 补齐+编排推进的完整协作。
2. rollback 的 revert 边合法性由 StateIO 按 state.md §3 判：若回退边在当前进度下非法（如 S1→S3 rollback），如实 ADVANCE 拒绝/记录，不造第二套迁移规则。
3. retry 仅适用 pending 工具执行失败（TOOL_ERROR），上限 1；RQG/loop 的内容性失败永不走 retry（指令 §24）。
4. Action 日志计数按文件行数续编，跨进程稳定但无并发锁（单 Agent 会话模型，与 state.yaml 写模型一致）。
5. Figure 接口不在 Phase 3（Phase 4 交付 `figure_iface.py`），S8 的 pending 执行目前只跑 trace/diagnose。
