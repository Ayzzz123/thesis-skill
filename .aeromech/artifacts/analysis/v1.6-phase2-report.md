## 2. 关键设计决定

1. **判定与执行分离**（本 Phase 核心纪律）：stage_routing 不调用任何 research 工具、不写任何文件。证据缺失输出 `SKIPPED_WITH_REASON` + 待运行工具名（`run_pending.run` 列表），由 Phase 3 Orchestrator 负责先运行——既堵住"没跑过=通过"的 false pass，也不越权执行。
2. **词表不重造**：item 级门禁 = v1.4.1 七态（feasibility 三态 FEASIBLE/CONDITIONALLY/INFEASIBLE 映射 PASS/WARN/FAIL）；s7 门禁沿用 state.md §5 的 passed/conditional/failed 原词；交付级 = 指令 §二十一 五态。无任何新造状态。
3. **证据即真值**：feasibility 读 `artifacts/analysis/research-diagnosis.json`、loop 读 `artifacts/analysis/research-loop-log.json`、RQG 读 `artifacts/qa/research-quality.json`——全部是 v1.4/v1.5 既有工具的真实落盘产物，字段名取自实际实现（`open_findings`/`gate`/`status`），routing 层零解析注册表语义（注册表统计一律走 research_context）。
4. **回退映射数据化**：`CATEGORY_TARGET`（state.md §8）+ `ISSUE_TYPE_TARGET`（v1.5 19 类 issue_type→阶段）。未知 issue_type 回落类别映射，不崩溃（防新类型加入即坏）。
5. **矩阵即配置**：`MATRIX` 是纯数据（可 `matrix` 子命令导出 JSON），Phase 3 orchestrator 消费它而不是 if-else 分支；S3→S7 review 型特例、S4→S7 literature_reviewed 特例都在数据里表达。

## 6. 已知限制（如实记录）

1. `delivery_gate_status` 目前只聚合研究侧五类门禁（feasibility/s7/rqg/agent_loop/human_review）；格式 QA 链（tf/cover/page/graph/pdf 等）与 figure QA 的接入是 Phase 4（统一 build 链产物落 qa_state 后并入）。指令 §二十一 的"全项统一进入 Delivery Gate"在 Phase 4 完成，本 Phase 先立五态框架与缺项 BLOCK 纪律。
2. loop BLOCK 的 revert 目标按 `open_findings.issue_type` 首条映射；多条时建议序未做优先级排序（v1.5 的 Research validity > Evidence > … 优先级链留 Phase 3 failure_recovery 消费 disposition）。

4. S1 的 feasibility 挂载在 design.yaml 未建时 NOT_APPLICABLE（题目级可行性初判仍是 Agent/RQG 语义职责），Phase 3 可把 `research_design.py` 的题目卡片模式接进 run_pending。
