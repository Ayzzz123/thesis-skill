## 2. 关键设计决定

1. **只增不破**：state schema 1.0 既有字段语义零改动；新增内容走 additive（`checkpoint.last_id` 字段、`school_requirement` 键、materials type 枚举扩展 school_notice/task_book/proposal——旧枚举值不变）。高 schema 版本按 state.md §10 只读保护。
2. **复用不重造**：注册表快照直接调 `research_integrity.load_all(collect_errors)`；模式判定直接调 `template_fidelity.select_docx_mode`；无第二个注册表/模式实现。
3. **诚实状态**：材料注册即 pending；提取不到=unknown；拒绝的迁移不写 history；损坏不静默当空表（RuntimeError→rc 3）。
4. **milestone 不重复门禁**（state.md §6 语义）：阶段内里程碑不重校验进入该阶段的前置。
5. **override 必挂问题**：强行推进缺项全部转 open_issue（severity=高）；无 override-note（确认记录）拒绝。

## 6. 已知限制（Phase 1 范围内如实记录）

1. `check_gate_evidence` 只做机械可判项（文件存在/非空/review 型 literature_status）；"证据完成判据"逐条语义核验仍属 Agent/RQG 职责（state.md §5 第 3 步本就非纯机械）。
2. 返程条件（触发回退的 issue 全部 closed）未逐边追溯——Phase 3 orchestrator 基于 history/issue_id 实施；本层仅词表级检查。
3. PDF/扫描件格式规范不做字段提取（设计决定，非缺口）：test-8.0 若给 PDF 规范，对应字段需人工核对录入或 Agent 阅读后写入 `fields`（格式已预留）。
4. `scan` 对空 school 目录外的大批量文件不做内容级去重（仅哈希），同文档不同哈希（如重新导出）会列 new——这是正确行为（材料变了），人工确认即可。
