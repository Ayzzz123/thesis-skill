## 0. 总体结论（TLDR）

v1.4.0~v1.5.0 的能力（Research Integrity / Research Intelligence / Agent Loop / Human Review / Delivery Gate 规则 / 22 个 QA 脚本）**在"单次调用"维度是完整的、经过验证的**。缺口全部集中在"跨调用、跨中断的项目级编排"维度：

1. **状态机是纯文档协议**：`state.yaml` 有完整 schema 与迁移规则（state.md），但**没有任何一行代码读写它**——迁移校验、门禁证据核验、恢复判断全靠 Agent 自觉遵守。test-4.0 的 `stage.current: S4` 与实际进度（history 已到 S9 里程碑、tf_qa 20 项 PASS）脱节，就是这种漂移的实证。
2. **没有 Orchestrator**：交付链顺序（build → update_toc → cover restore → repaginate → export_pdf → 12 个 QA → finalize → Gate）只写在 delivery-pipeline.md 的散文里，由 Agent 逐条手工执行；仓库中不存在任何 pipeline runner 脚本。
3. **没有代码级 Checkpoint/Resume**：中断恢复只有 state.md §11/§12 的人工备份协议；`research_agent_loop.py` 是唯一的"循环"，但它不持久化迭代状态、不触碰 state.yaml。
4. **文档构建是逐项目手写的**：test-3.0~7.0 每个项目都有自己的 `build_docx_*.py` / `gen_figs_*.py` / `calc_*.py`（放在项目根或 transcripts/），互不复用；通用的只有 docx_engine / template_fidelity 原语层。
5. **Figure 无机器接口**：plan 是散文 md（figure-plan.md，没有任何脚本读它），generate 是各项目的 bespoke 脚本（硬编码绝对路径），validate 是独立 CLI（graph_quality_qa 等），三个环节没有程序化接缝。协作者分支 `feature-1.6.0-figure-generation` 本地与 origin 均不存在 → 其现状 UNKNOWN。
6. **Delivery Gate 没有统一执行体**：Gate 规则散布在 delivery-pipeline §7/§8.1/§8.2/§8.3 + SKILL §16/§19/§20，各 QA 脚本各出各的报告，"汇总所有 QA + 人工队列 → 五态终局"这一步目前由 Agent 人工判读。

这些正是 v1.6.0 "FULL-STACK THESIS ORCHESTRATION" 要补的层。v1.4/v1.5 的注册表、RQG、诊断、修复、Loop、评分、NHR 双队列、22 个 QA 脚本、sync 规程**全部复用，不重做**。

### 1.2 Research Integrity（v1.4/1.4.1）

✅ 完整且被脚本消费：13 注册表引擎（`research_integrity.py`：init/validate/trace/coverage，REGISTRY_SPECS 单一真源）、RQG-00~15（`research_quality_qa.py`）、模拟身份四规则、traceability.json、Evidence Coverage 四分类、冲突登记。旧项目未初始化 rc=2 不阻塞。**结论：v1.6 直接复用，注册表接口是唯一需要的接缝。**

### 1.3 Research Intelligence（v1.5）

✅ 完整：design/scope/repairs 注册表、`research_design.py`（audit + RF-01~10 feasibility）、`research_diagnosis.py`（19 issue_type、severity 归一、稳定 DIAG ID、auto/queue/block disposition）、`research_repair.py`（白名单 4 操作 + before/after 留痕 + 受控 recompute）、8 维评分。test-7.0 植入 7 缺陷全部捕获。**结论：复用；Orchestrator 只做调度与结果消费，不复制其逻辑。**

### 1.4 Agent Loop

✅ 单次调用内闭环完整：PLAN→ANALYZE→DETECT→DIAGNOSE→REPAIR→RE-ANALYZE→VALIDATE→ACCEPT，≤5 轮，签名无改善即停，终态 BLOCK(rc1)/PASS_WITH_HUMAN_REVIEW/WARN/PASS_WITH_WARNINGS/PASS；loop-log（md+json）落盘；已裁决队列条目持久保留（B10）。
❌ **跨调用不可恢复**：不持久化轮次游标；中断即整轮重来（幂等代价低，但没有"上次停在第几轮、修了什么"的对外契约）。
❌ **失败不回传状态机**：loop BLOCK 后"按 issue→target_stage 映射回退"是规则文字（state.md §17.1 第 4 条、delivery-pipeline §8.3），无代码执行——回退、重入阶段、修复后重跑由 Agent 手工串联。**这是 Failure Recovery 的核心缺口（G-REC-1）。**

### 1.5 材料管理

✅ 规则完整：materials.yaml schema（MAT-XXX、availability/type/authority L1-L5/verification_status/hash_or_identifier/used_by）、Project Directory Contract（materials/ 六子目录 + 旧结构兼容）、禁止修改原始文件、模板样例只做格式参考。

### 1.6 模板处理 / School Requirement Parsing

✅ 双模式成熟：`select_docx_mode()`、TEMPLATE_FIDELITY 母版驱动、FORMAT_RECONSTRUCTION 重建、冲突优先级（正式规范>模板结构>样例文字>Skill 默认）、`template_vs_spec_conflict` 记录、legacy .doc 转换。三层格式模型（general_principles / general_defaults / school_specific_unknown + format_source: school_template|sample_thesis|general_default|unknown）**在 schema 层面已经区分了 official/sample/default**——满足"不得把样例当正式要求"的规则表达。

## 3. 约束与风险登记

1. **稳定模块纪律**（v1.5 plan 的 STABLE_MODULES 清单）：tf_qa/template_fidelity/cover 链/页图表格 QA/purity/pdf_qa/RI 引擎/RQG/NHR/sync —— v1.6 不得改其行为；确需触碰（如 visual_regression 的 EXEMPT 硬编码）以"新回归用例 + t30~t60 重跑"为前提，最小修改。
2. **state schema 只增不破**：checkpoint/gate 记录走**新增字段**（schema 1.0→1.1 additive，遵循 state.md §10 迁移协议）或独立工件文件，不改既有语义；旧项目（无新字段）必须照常可读。
3. **不硬编码、不为 test-8.0 写特例**：调度矩阵、失败策略、QA 链 manifest 都是数据文件；visual_regression 的页面豁免若改造，须改为规则化（章节起始页探测）而非项目索引。
4. **开发/安装双目录**（v1.4.1 规程）：新代码落 dev 权威源，测试后 `sync.py --to-install`；`test_dev_install_sync` 是回归一部分。
5. **Word COM 依赖**：update_toc/repaginate/export_pdf/convert_legacy_doc 需本机 MS Word——orchestrator 必须把 COM 步骤的失败分类为 ENV/ERROR 而非内容 FAIL。
6. **协作者分支不在仓**：origin 仅 featureyyy/featurezzz/main/master（无 feature-1.6.0-figure-generation）。接口按其独立演进设计；本地默认适配器保证主线自足（render_mermaid + figkit 项目脚本 + QA 校验），Provider 换实现不破主线。
7. **content_purity INT-01** 把 "thesis-test" 当泄露 token 扫描：test-8.0 产物命名注意与历史项目同样规避（项目目录名不受影响，正文内不得出现）。
8. **UNKNOWN 清单**（按指令 §28 显式标记）：
   - U1 协作者 figure 分支的模块形态与 API → UNKNOWN，以 §20 指令的最小接口（plan/generate/validate）为契约。
   - U2 school 材料为扫描件/PDF 图片型时格式参数可提取度 → UNKNOWN（parser 对不可提取字段落 unknown，不猜）。
   - U3 test-8.0 具体题目 → 由 Agent 在冷启动运行时依材料独立确定（指令 §十八明文，不预先钉死）。
   - U4 v1.5 报告所称"13 测试文件 418 断言"在当前 checkout 的复跑基线 → 进入实现前先跑一次 v1_4/v1_4_1/v1_5 全量作为 phase-1 门禁（本审计未执行测试）。
